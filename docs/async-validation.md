# 비동기 CARLA 검증 기록

이 문서는 독립 참조 런타임과 같은 최신 결과·신선도 제한·native 폴백
원칙을 로컬 연구 통합체에 적용한 통제 실험의 집계 결과다. 제3자 코드,
설정, 원본 로그, 이미지, 영상 또는 모델 가중치는 포함하지 않는다.

## 조건

- 초기 VLM: 로컬 범용 Qwen2.5-VL 3B
- 후속 VLM: 로컬 파인튜닝 Qwen2.5-VL 7B
- VLM 요청 주기: 제어 10프레임
- 결과 최대 나이: 60프레임
- 입력과 결과 mailbox: 각각 최신 항목 1개
- 연속 궤적과 PID 제어: base planner 유지
- 회전 명령: 현재 route 명령과 일치할 때만 허용

첫 실험은 범용 3B 모델로 스케줄링과 안전 폴백을 검증했다. 이후
보관 디스크에서 기존 파인튜닝 7B 가중치를 복구해 동일한 비동기
설정으로 의미 명령 개입까지 추가 검증했다. 가중치와 원본 산출물은 이
저장소에 포함하지 않는다.

## 범용 3B 폴백 결과

| 경로 | 제어 프레임 | VLM 결과 | 결과 나이 | 오류/드롭/폐기 | 경로/페널티/종합 |
|---|---:|---:|---:|---:|---:|
| Town12 ParkingExit | 587 | 59 | 모두 2프레임 | 0 / 0 / 0 | 100 / 1.0 / 100 |
| Town12 BlockedIntersection | 484 | 49 | 모두 2프레임 | 0 / 0 / 0 | 100 / 1.0 / 100 |

두 최종 평가 레코드는 모두 `Completed`였다. 충돌, 경로 차선 이탈,
신호 위반, 정지 표지 위반, agent blocked, timeout은 0이었다. 교차로
경로에서는 장애물 앞에 147프레임 정지한 뒤 재출발했고, route와 유효
planner 명령이 45프레임 동안 함께 `right`였다.

## 해석과 한계

범용 3B VLM은 모든 표본에서 `straight`만 출력했다. 이 명령은 현재
route와 맞지 않아 회전 게이트가 차단했고, 두 주행은 native planner의
명령과 target을 유지한 채 완주했다. 따라서 다음은 검증됐다.

- 제어 루프가 VLM 호출 경로와 분리되어 끝까지 실행된다.
- 완료된 VLM 결과가 프레임 식별자와 함께 소비된다.
- 결과 나이가 제한 안에 유지되고 오류나 backlog가 누적되지 않는다.
- 잘못된 의미 명령이 route gate를 넘어 target을 오염시키지 않는다.

이 두 실험은 폴백 검증이며 VLM 개입 효과의 검증은 아니다.

## 파인튜닝 7B 개입 결과

| 경로 | 제어 프레임 | VLM 결과 | 결과 나이 | 오류/드롭/폐기 | 경로/페널티/종합 |
|---|---:|---:|---:|---:|---:|
| Town12 ParkingExit | 583 | 59 | 모두 2프레임 | 0 / 0 / 0 | 100 / 1.0 / 100 |
| Town12 BlockedIntersection | 497 | 50 | 모두 2프레임 | 0 / 0 / 0 | 100 / 1.0 / 100 |
| Town13 VehicleOpensDoorTwoWays | 376 | 38 | 모두 2프레임 | 0 / 0 / 0 | 100 / 1.0 / 100 |

ParkingExit에서는 `change_lane_left` 결과가 연속 확인을 통과해 16프레임
동안 유효 명령이 됐다. 다만 출차 초기의 정지 구간이었고 유효한 기존
route-aligned target이 있어 target을 임의로 바꾸지 않았다.

BlockedIntersection에서는 경로와 맞지 않은 요청 269프레임을 게이트가
차단했다. 실제 교차로 구간에서는 VLM, route, 유효 planner 명령이 51프레임
동안 모두 `right`였고, 해당 51프레임 전체에서 검증된 `map_branch` target이
적용됐다. 장애물 앞에서 대기한 뒤 재출발해 100% 완주했고 충돌, 차선 이탈,
신호·정지 표지 위반, agent blocked, timeout은 0이었다.

VehicleOpensDoorTwoWays에서 VLM 결과는 `lane_follow` 30회,
`change_lane_left` 7회, `stop` 1회였다. `change_lane_left`가 시간적 확인을
통과해 60프레임 동안 유효했고, 같은 구간에 검증된 왼쪽 인접 차선 target과
제한된 waypoint 보정이 적용됐다. 보정량의 최댓값은 1.057 m로 설정한 2 m
한도 안이었다. 차량은 열린 문을 피해 경로 전체를 완주했으며 충돌, 차선 이탈,
agent blocked, timeout은 0이었다.

한 번의 `stop` 결과는 이미 정지해 있던 시점에 나왔고 연속 확인을 통과하지
않았다. 따라서 이 경로의 VLM 개입 증거는 정지 명령이 아니라
`change_lane_left`와 이에 따라 검증·적용된 target 및 궤적 보정이다. VLM은
연속 궤적이나 조향·가감속 값을 직접 만들지 않았고, 이는 기존 planner와
저수준 제어기가 담당했다.

세 MP4도 1980×540, 20 fps로 전체 디코딩했으며 각각 583/583,
497/497, 376/376프레임이 정상이었다. 동영상 자체는 이 저장소에 포함하지
않는다.

## 해석과 한계

이 결과는 파인튜닝 VLM의 도움이 되는 명령이 비동기로 소비되고, 검증 조건을
만족할 때 기존 planner의 명령 제약, target 또는 제한된 궤적 보정에 실제로
반영되며, 조건을 만족하지 않을 때 native 경로를 유지하는 것을 보여준다.
다만 세 개의 통제된 단일 경로 실험이므로 전체 Bench2Drive 성능 향상이나
native planner 대비 성능 우위를 입증하지는 않는다.

느린 wall-clock 추론 때문에 evaluator 콘솔의 traffic-relative
`MinSpeedTest` 진단은 실패로 표시됐지만, 세 최종 레코드의 상태와 종합
점수에는 영향을 주지 않았다.
